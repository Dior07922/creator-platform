# 修改记录

## 2026-09-22 创作单元整体拖动（Unit 外框拖动）

### 背景

智能合成（`synth-*`）产出「创作单元」（`Unit`），画布上以浅色虚线包围框 + 名字小标呈现。此前 Unit 只能通过"框选全部成员再拖组"或"排列命令"间接移动，外框本身不可直接拖动。

### 坐标真相确认

- `Unit` 结构：`memberIds`（引用 page 各元素数组的 id）+ `bbox`（由成员计算的派生缓存），**没有 `x`/`y`/`items[]` 字段**。
- 成员真实坐标唯一存在于 `page.images / notes / tables / links / shapes` 里（纸张局部坐标）。
- 连线渲染（`centerOf`）、命中检测、框选、播放全部读成员当前坐标，与 Unit 无直接依赖。

### 实现（`src/components/creation/Editor.tsx`，单文件增量）

1. **命中**（`hitUnitBorder`）：落点在 Unit 包围框外扩 12px 的**环形命中带**内（外扩 bbox 内、收缩 bbox 外）才识别为 Unit 外框；内部空白保持原有操作（框选 / 双击建文字）。多 Unit 重叠时取落点距外框边缘最近者。成员命中优先级高于 Unit（成员分支先 return）。
2. **状态**（`gRef.unitDrag`）：记录 `unitId` + 成员初始坐标快照 + 起始 pointer 位置。独立于 `selectedEl`，不扩 selectedEl 类型体系。
3. **拖动**（`applyUnitMemberMove`）：屏幕 delta → 纸张局部 delta（旋转补偿 + 缩放归一，与 `dragShape` 分支同款换算），一次性平移全部成员的真实坐标（image/note/table/link/shape 五类数组单次 `onUpdate` 提交）；bbox 同帧直接平移（`+ldx/+ldy`），外框实时跟随，成员相对位置不变，不吸附、不回正、不改 z 层级、不改 memberIds。
4. **结束**：
   - `pointerup`：成员坐标已逐帧提交（手停哪停哪），只做 `syncUnitBboxes` 最终校准 + 清状态。
   - `pointercancel`：不还原，保留当前位置，同样做 bbox 最终校准。
5. **性能 / 撤销**：拖动中每帧一次 `onUpdate`（成员 + bbox 同一批次），不写历史；一次 Unit 拖动在 `onUpdate` 层是成员移动 N 帧 + 最终校准 1 条，**不产生逐帧 history 条目**（历史栈在 `applyDoc` 层按文档 diff 管理，与现有排列命令一致）。
6. **视觉**：拖动中该 Unit 外框加浅色填充 + 边框加粗变实色，松手恢复；命中带仅逻辑区，视觉外框不变粗。

| 9 | undo 一次撤销整个 Unit 拖动 | ⚠️ 见下方说明 |
| 10 | touch 真机拖动无延迟、无回弹 | ⚠️ 需真机验证（pointer capture + `touchAction:none` 已配置） |

**说明 #9**：本实现中成员平移在 `onUpdate`（`applyDoc`）层逐帧提交，与现有单元素 `dragShape` 行为一致（该路径同样不逐帧写 shape history，单元素拖动也是松手后一次历史）。Unit 拖动比单元素多 N 个成员，但每个成员各自一条 diff，**撤销粒度 = 撤销最后一次 `onUpdate` 批次**（与排列命令 `align-*` 的多成员 `setPos` 行为一致）。若后续需要"一次撤销整个 Unit 拖动"的严格单条目粒度，需在 `applyDoc` 历史层加一个 `unit-move` 事务包装，本轮未做（属于历史系统改造，超出本轮范围）。

### 不做的

- `useCreationStore`（不存在该 store，store 层为 `applyDoc` 函数式更新）
