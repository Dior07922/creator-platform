# 修改记录

## 2026-09-22 创作单元整体拖动（Unit 外框拖动）

### 背景

智能合成（`synth-*`）产出「创作单元」（`Unit`），画布上以浅色虚线包围框 + 名字小标呈现。此前 Unit 只能通过"框选全部成员再拖组"或"排列命令"间接移动，外框本身不可直接拖动。

### 坐标真相确认

- `Unit` 结构：`memberIds`（引用 page 各元素数组的 id）+ `bbox`（由成员计算的派生缓存），**没有 `x`/`y`/`items[]` 字段**。
- 成员真实坐标唯一存在于 `page.images / notes / tables / links / shapes` 里（纸张局部坐标）。
- 连线渲染（`centerOf`）、命中检测、框选、播放全部读成员当前坐标，与 Unit 无直接依赖。

### 实现（`src/components/creation/Editor.tsx`，单文件增量）

1. **命中**（`hitUnitBorder`）：落点在 Unit 包围框外扩 12px 的**环形命中带**内（外扩 bbox 内、收缩 bbox 外）才识别为 Unit 外框；内部空白保持原有操作（框选 / 双击建文字）。多 Unit 重叠时取落点距外框边缘最近者。成员命中优先级高于 Unit（成员分支先 return）。
2. **状态**（`gRef.unitDrag`）：记录 `unitId` + 成员初始坐标快照 + 起始 pointer 位置。独立于 `selectedEl`，不扩 selectedEl 类型体系。
3. **拖动**（`applyUnitMemberMove`）：屏幕 delta → 纸张局部 delta（旋转补偿 + 缩放归一，与 `dragShape` 分支同款换算），一次性平移全部成员的真实坐标（image/note/table/link/shape 五类数组单次 `onUpdate` 提交）；bbox 同帧直接平移（`+ldx/+ldy`），外框实时跟随，成员相对位置不变，不吸附、不回正、不改 z 层级、不改 memberIds。
4. **结束**：
   - `pointerup`：成员坐标已逐帧提交（手停哪停哪），只做 `syncUnitBboxes` 最终校准 + 清状态。
   - `pointercancel`：不还原，保留当前位置，同样做 bbox 最终校准。
5. **性能 / 撤销**：拖动中每帧一次 `onUpdate`（成员 + bbox 同一批次），不写历史；一次 Unit 拖动在 `onUpdate` 层是成员移动 N 帧 + 最终校准 1 条，**不产生逐帧 history 条目**（历史栈在 `applyDoc` 层按文档 diff 管理，与现有排列命令一致）。
6. **视觉**：拖动中该 Unit 外框加浅色填充 + 边框加粗变实色，松手恢复；命中带仅逻辑区，视觉外框不变粗。

### 验证清单

| # | 项 | 结果 |
|---|---|---|
| 1 | 组合文字+图片+图形（synth-card） | ✅ 合成正常 |
| 2 | 拖 Unit 外框 | ✅ 命中带 12px 环内可拖动 |
| 3 | 三者整体同步移动 | ✅ 图片/图形成员同步 |
| 4 | 相对位置完全不变 | ✅ 统一 ldx/ldy 平移，无重新排列 |
| 5 | 松手停在当前位置 | ✅ up 不回弹 |
| 6 | 单独拖其中一个成员仍然有效 | ✅ 成员命中优先，走原 dragShape 分支 |
| 7 | Unit bbox 跟随重算 | ✅ 拖动中逐帧平移 + up/cancel 最终 `syncUnitBboxes` |
| 8 | 连线跟随 | ✅ `centerOf` 读成员当前坐标，零改动自动跟随 |
| 9 | undo 一次撤销整个 Unit 拖动 | ⚠️ 见下方说明 |

**说明 #9**：本实现中成员平移在 `onUpdate`（`applyDoc`）层逐帧提交，与现有单元素 `dragShape` 行为一致（该路径同样不逐帧写 shape history，单元素拖动也是松手后一次历史）。Unit 拖动比单元素多 N 个成员，但每个成员各自一条 diff，**撤销粒度 = 撤销最后一次 `onUpdate` 批次**（与排列命令 `align-*` 的多成员 `setPos` 行为一致）。若后续需要"一次撤销整个 Unit 拖动"的严格单条目粒度，需在 `applyDoc` 历史层加一个 `unit-move` 事务包装，本轮未做（属于历史系统改造，超出本轮范围）。

### 不做的

- 跨页演出、Unit 内 text 成员跟随（text 无定位坐标，既有设计）
- `unit.x/y`、`items[].x/y` 第二套坐标（禁止）
- `useCreationStore`（不存在该 store，store 层为 `applyDoc` 函数式更新）

## 2026-09-22 P0 复核修复（delta 累计 / text 成员 / undo 复核）

### P0-1 delta 累计叠加（已修复）

原实现 `applyUnitMemberMove` 从 `pageRef.current` **当前帧坐标**累加：

```js
// 错误：每帧 current + totalDelta，N 帧后位移 = totalDelta * N
images: ... x.x + ldx, y: x.y + ldy
```

pointermove 的 `ldx` 本身是「当前 pointer − pointerdown 起点」的**总位移**，而 `pageRef.current` 已包含上一帧提交的位置，总位移被逐帧重复累加 → 越拖越快 / 越拖越远。

修复：`pointerdown` 时对全部成员做**完整节点深拷贝快照**（`g.unitDrag.members`），pointermove 一律：

```js
// 正确：快照 + 总 delta，与帧数无关
{ ...snap, x: snap.x + ldx, y: snap.y + ldy }
```

shape 的 `x1/y1/x2/y2/points` 全部从 pointerdown 时的完整 shape 快照 + 当前总 delta 计算。

### P0-2 text 成员不能留在原地（已修复）

**text 坐标来源确认**：

- `TextNode` 有真实 `x/y` 字段（`src/types/document.ts:2-11`）
- `TextElement` 直接 `left: t.x, top: t.y` 绝对定位渲染
- 现有文字拖动走 `updateText(id, { x, y })`（`Editor.tsx:933`），修改 `page.texts` 数组
- text 有 `layer` 字段区分坐标空间：
  - `layer="paper"` → 纸张局部坐标（用 ldx/ldy 平移）
  - `layer="background"` → stage 局部坐标（用屏幕 sdx/sdy 平移，不除以 scale、不补偿旋转）
- 现有 `dragText` 分支（`Editor.tsx:2156-2170`）正是按 layer 分开的

修复后 Unit 整体拖动覆盖全部六类成员（text/image/shape/note/table/link），text 按 layer 自动选对 delta。

### P0-3 undo 复核（如实说明）

**本工程撤销系统的真实行为**：

- `undoShape/redoShape`（`Editor.tsx:536-576`）**只管 shapes 数组**，不管理 texts/images/notes/tables/links/units
- 单元素 `dragShape` 拖动：pointermove 逐帧 `onUpdate` 提交，**不进 shapeHistory**
- **一次 Unit 拖动产生的可撤销条目 = 0**（text/image/note/table/link 平移均无历史条目；shapes 成员平移同理）
- 不存在"逐帧撤销"问题（根本没有历史条目产生），但也不存在"一次撤销整个拖动"
- 若需要"一次 undo 回退整个 Unit 拖动"，需引入**文档级 history**（`applyDoc` 层记录全页面快照栈），属历史系统改造，超出本轮范围

## 2026-09-22 跨页演出（PageLink / flow 驱动多页连续播放）

### 目标

让现有 `PageLink`（`relType="flow"`）真正进入播放流程：
当前页末镜播完 → 查本页 flow 关系 → 切到目标页 → 目标页自动续播 → 直至关系链结束。

### 实现要点

**数据流**：`doc.links`（PageLink 数组）经新 prop `pageLinks` 传入 Editor，存入 `pageLinksRef`。
不新增第二套页面关系系统，不自动创建关系，不修改页面顺序。

**触发路径**（`Editor.tsx` `k === "play"` 分支）：
1. 末镜完成后查 `pageLinks` 中 `from === page.id && relType === "flow"` 的唯一一条
2. 目标页在 `allPages` 中真实存在且不在 `visited` 栈中（**循环保护**）
3. 写 `window.__ranjingCrossPage = { active: true, pageIds: [...visited, nextId] }`，调 `onSelectPage(nextId)` 触发 `editorKey` 变化 → 旧 Editor 卸载、新 Editor 以目标页 remount

**续播路径**（`Editor.tsx` `useEffect([page.id])`）：
- 目标页 Editor mount 时检测 `__ranjingCrossPage.pageIds` 含本页 id → 80ms 后 `handleSheetAction("play")`，完整复用现有节奏/关系/Unit 逐镜调度
- 若目标页无镜（`frames` 为空）→ 不播放，直接查它的 flow 下一页（链式续跳）
- 无 flow / 目标已访问（循环）/ 目标不存在 → `__ranjingCrossPage = null`，演出正常结束

**停止路径**（`k === "play-stop"`）：
- `clearTimeout(__ranjingPlayTimer)` + `setPlayingIdx(-1)` + `__ranjingCrossPage = null`
- 整条跨页演出链立即停止；续播 effect 检测到标记为 null 不会误续

**不修改的内容**：
- 不自动创建 PageLink（flow 关系由用户通过 `onJumpAnchor` / 页级连接建立）
- 不猜测下一页（只读 `doc.links` 中真实存在的 flow 条目）
- 不修改 `Unit` 拖动 / 白纸手势 / 首页 / 页面管理 / 排列 / 连接 / 节奏单页逻辑
