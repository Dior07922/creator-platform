# 技能商城设计决策

## 已确定

- 删除外挂式方形“苒印”。欢迎页和登录页统一使用可复用 `BrandWord` 品牌字组件；在没有定制字形或可靠 SVG 笔画前，采用纯墨色“苒境”，不得用定位红点、边框、印章或图标模拟“字内藏红”。未来若制作正式定制字形，可再评估极小面积朱砂笔画。
- 登录页“苒境”固定为约 21px，只作为品牌签名，不再承担大标题作用；登录页其他结构和功能保持封版。
- 苒境欢迎首页最终文案固定为“苒境 / 山外，还有山。/ 进入苒境 →”，不得删改或增加其他文案。页面使用白色、浅灰水墨远山、雾、飞鸟、水面和小舟；背景图不嵌文字，全部文案由前端真实文字呈现。点击“进入苒境 →”进入手机号验证码登录页。
- 入口顺序固定：首次打开为欢迎页；点击后在客户端记录已看过。未登录用户后续直接进入手机号登录页；有效会话用户直接进入首页。欢迎页观看状态不进入账号数据库。
- 手机号验证码验证成功同时承担注册和登录：新手机号创建唯一商城用户并进入完善资料页，老手机号直接进入首页；全 APP 共用一个 HttpOnly 服务端会话。
- 苒境统一登录页采用“安静入口”：暖白、墨灰、纸张感和大留白，只保留手机号、验证码、进入按钮与轻量协议说明；不做营销页、科技感登录页或登录/注册双 Tab。
- 登录页不承担品牌情绪说明，删除副标题“创作、发现，也让好的能力被看见”；品牌世界观只由欢迎页表达，登录页不得增加替代说明文字。
- 未注册手机号验证成功后自动创建账号；新用户首次只补充可跳过头像和昵称，实名认证仅在入驻、提现或依法需要时触发。
- 「我的」V1 采用“个人扉页”结构并封版。除非功能变化要求调整结构，否则不再修改其视觉。
- 技能商城只有一套商城用户账号。用户第一次打开 APP 时完成商城注册/登录；首页、资源、创作、设计、我的五个一级页面共用该登录状态，商城内部不得反复要求注册。
- 三种身份必须分开：`商城账号 = 整个 APP 的用户身份`；`入驻申请 = 已登录用户申请出售技能的经营身份`；`外部平台账号 = 用户连接对应内容平台时由平台官方处理的身份`。
- “我的 → 申请入驻”只能称为申请入驻、入驻资料或入驻审核，不得称为再次注册商城账号，也不影响普通用户进入创作区。
- 创作入口分为两类：微信公众号、百家号、知乎、头条、微博、小红书、读者是平台型创作；小说、短剧是商城内部创作。
- 平台型创作在商城账号已登录后，进入所选平台的官方注册/登录或正式开放平台授权流程；商城不得仿造第三方登录页，不得收集或保存第三方账号密码，不得伪造授权成功状态。
- 小说、短剧不依赖外部平台账号。商城账号已登录后直接进入对应创作区，不得要求第二次注册或登录。
- 登录前是商城的公共创作入口；登录后才进入用户自己的作品、正文、章节、人物、大纲及其他创作数据。产品名称统一理解为“我的创作空间”，不是孤立的“码字工作台”。
- 外部平台正式授权时必须安全保存用户原来选择的创作通道和商城内部返回地址；授权完成后返回对应创作区。若暂时只有官方网页登录入口，应明确显示“前往官方平台”和返回商城的方法，不得假装已经完成连接。
- 账号接入不得破坏现有小说数据。浏览器旧稿迁移到账号前必须采用可确认、可回退的一次性迁移方式，不得把同一浏览器的旧稿自动归给任意登录用户。
- 商城账号第一版只使用手机号 + 短信验证码；不做邮箱注册、邮箱登录或用户名密码登录。
- 邮箱不是身份，只是数字商品收货信息。确认订单必须填写接收邮箱；用户可选择“保存此邮箱，下次购买自动填写”，保存结果只能属于当前商城用户。
- 数字商品必须同时交付到订单详情和本次接收邮箱，邮箱不能成为唯一取货方式；邮件服务未接入时不得显示发送成功。
- 用户信息、创作偏好和使用习惯可以作为长期维护与产品升级依据，但必须遵守“明确告知、用户授权、只收集必要信息、可查看、可关闭、可更正、可导出、可删除”的原则；不得记录密码、验证码、正文按键过程或与产品无关的隐私数据。
- 用户长期记忆与账号核心数据分开管理。账号、安全、作品数据属于必要数据；偏好画像和行为分析属于可选择数据，用户关闭后不得继续新增记录。
- 创作底层只有一套，各通道前台按用途变化；小说的章节、人物和大纲不得错误出现在其他平台创作区。
- 首页热点不直接把用户送出商城。固定路径为：`全网热点 → 商城内热点详情 → 查看原始新闻`。
- 商城内热点详情是一级首页与外部原文之间的承接层，负责呈现来源、更新时间、热度、标题与摘要；不复制新闻全文。
- 查看原始新闻是明确标注的次级外链。原文链接缺失或失效时，内部详情仍需正常打开。
- “加入素材”“用这个热点开始创作”等能力属于后续扩展，不进入当前 V1 路径闭环范围。
